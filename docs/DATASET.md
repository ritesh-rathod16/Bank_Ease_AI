# Dataset (synthetic only)
- **Source:** generated by `scripts/make_datasets.py` (fictional lenders, borrowers, addresses, account IDs; every page footer says SYNTHETIC). No real data, no downloads, no licenses involved.
- **Regenerate:** `python scripts/make_datasets.py [--out data/samples]` (PDFs use `invariant` mode; a test confirms expectations regenerate identically).
- **Counts:** 22 PDFs + 2 non-PDF-content files (`not_a_pdf.pdf`, `empty_file.pdf`) = 24 files; 7 comparison pairs; manifest.json + manifest.csv.
- `data/samples/statements/review_flags.csv` is a separate fictional CSV fixture for statement import; it contains four transactions including one deliberate running-balance mismatch and one duplicate candidate. It is not part of the PDF manifest or training data.
- The PDF statement parser tests generate a fictional ruled-table statement in memory at test time. It is not a retained training artifact or part of the manifest; it checks table extraction, page evidence, arithmetic, and the unsupported-layout review path.
- **Ground truth:** derived from how each document is constructed (independent EMI formula in the generator), not from the app's extractor. Manifest per file: scenario, expected HTTP status, doc type/category, page count, unreadable pages, expected terms (value/status/page), expected clauses (category/page), expected Q&A (incl. unsupported questions), expected EMI check; top-level `comparisons`.
- **Limitations:** templated wording (real contracts vary far more), digital-text PDFs only, "scanned" files are rasterized renders (not camera noise), INR amounts only, English only. Passing these tests does not imply accuracy on real documents.

## ML preparation and source candidates

`scripts/prepare_ml_dataset.py` creates runtime-only JSONL corpus files with source hashes, synthetic provenance, document and field labels, source evidence, and deterministic source-family splits. It refuses documents without the expected synthetic marker and validates the manifest, path, PDF signature, checksum, and page count. The currently accepted corpus is 20 PDFs with 140 expected field labels over three layouts. Whole-layout grouping produces 17 agreement documents in train, 2 sanction letters in validation, and 1 repayment schedule in test. Each split has only one class because type and layout are coupled, so this data is **not training-ready** and cannot support an honest held-out model benchmark.

External candidates and their limits/license-review status are tracked in [`ML_TRAINING.md`](ML_TRAINING.md). None has been downloaded or approved. In particular, repository-level license information must not be assumed to cover underlying financial reports, article images, or mirrored dataset artifacts.

## Held-out layout-family corpora

`scripts/make_layout_variants.py` creates 9 additional fictional PDFs in three independent text-layout families. Each family has one loan agreement, one sanction letter, and one repayment schedule with construction-derived field labels. The split keeps each entire family in only one partition, producing 3 documents/21 field labels in each of train, validation, and test with all three document types represented. The script and manifest are runtime-generated under `data/runtime/ml/layout-variants-v1/`; no customer data is involved. These 9 examples make a useful leakage and evaluator smoke check, but they are far too small and not human-reviewed, so the split manifest continues to block model training.

For an isolated experiment, the generator can create 67 parameterized variants (201 PDFs, 1,407 field labels). The family-level split has 47 documents per class in train and 10 per class in validation and test. The generator reuses three base layout styles across all partitions, so the test is not a holdout of unseen layouts or independent banking sources. Every label is construction-derived and unreviewed; training requires an explicit research-only override. GPT-2 LoRA was trained on this data and evaluated on the held-out 30 variants, but it performed worse than the existing title rules. See [ML training](ML_TRAINING.md) for the command, metrics, and limitations. Runtime corpus and adapter artifacts remain under ignored `data/runtime/ml/`.
