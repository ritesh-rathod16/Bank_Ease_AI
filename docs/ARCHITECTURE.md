# Architecture

## Runtime

```text
Browser
  └─ Next.js App Router (React + TypeScript + Tailwind, port 3000)
       ├─ Public pages and account flows
       ├─ TanStack Query + typed API client
       └─ same-origin rewrites (/api, /documents, /health)
            └─ FastAPI (port 8000)
                 ├─ Argon2id account auth and opaque cookie sessions
                 ├─ CSRF-protected mutations and owner-scoped document routes
                 ├─ PDF parsing, deterministic extraction, retrieval, EMI, comparison
                 └─ JSON development repository or optional MongoDB repository
```

The Next.js server rewrites browser API calls to FastAPI, keeping cookies on the browser's frontend origin. `BANKEASE_API_ORIGIN` configures the upstream API. `npm run dev:all` starts the API and frontend together. The backend no longer serves the application UI.

## Dashboard

The shell provides responsive sidebar navigation, authenticated profile/sign-out actions, Ctrl/Cmd+K evidence search, and a desktop right-side assistant. Summary counts and documents come from `/api/v1/dashboard/summary`; global search calls `/api/v1/search`, which reloads records only within the authenticated owner's scope. Loan values and the annual principal/interest chart come from extracted terms and the deterministic EMI schedule endpoint. Explicitly labeled loan installment, maturity, and interest-reset dates retain page evidence; ambiguous dates are marked for review, and only a future date manually confirmed by the owner appears in the calendar. A policy expiry appears as a renewal obligation only after owner confirmation; the calendar does not generate recurring payment dates. The assistant stores owner-scoped general or document conversations in MongoDB or local JSON, binds document chats to up to five supported owned documents, rechecks access to every selected source on reads and sends, and restores history after reload. It streams through the authenticated backend when a configured provider is available and otherwise retains deterministic document extraction or returns a clear model-unavailable error. Text-document retrieval is lexical BM25; statement questions retrieve owner-scoped rows and can run deterministic reconciliation checks. Sources identify filename and document plus a PDF page, worksheet/row, statement row, or calculation. Citation labels are checked against retrieved source IDs but not semantically entailed. Deleting any source removes linked conversations and messages.

## Data flow

The browser uploads PDF, PNG/JPEG/TIFF image, CSV, or XLSX bytes through the authenticated API. FastAPI validates size and file signatures/containers, parses selectable PDF text, converts raster images to a temporary in-memory PDF for bounded Tesseract OCR, imports CSV or read-only OpenXML statement rows, or extracts recognized PDF statement tables. XLSX processing rejects macros/external workbook links, never evaluates formulas, and retains the worksheet and source row for each transaction. Explicit insurance policy titles or multiple labeled policy identifiers activate a bounded rules-based field and clause extractor; conflicting or ambiguous values remain for review. Policy values retain source passage and page, and renewal dates require owner confirmation before entering the calendar. For a fully scanned statement with recognized headers, OCR word coordinates are grouped by visual line and assigned to columns; values pass through the same strict CSV normalization and reconciliation rules. OCR rows retain page, raw recognized text, row bounding box, and extraction method, and the statement remains in `needs_review`. Mixed scanned/selectable-text pages and unsupported layouts are not combined automatically. Accepted originals are stored under generated names retaining only an allow-listed source extension in private local `data/runtime/uploads`; the database stores only the generated key, extension, media type, and byte count. The authenticated inline preview checks the current owner before opening the file, and deletion/account deletion/retention purge remove the file and its derived records. Files are not encrypted at rest; Windows ACLs have not been independently verified. The document worker runs bounded retention sweeps at `BANKEASE_RETENTION_SWEEP_SECONDS` (default 900); uploads also sweep expired records for their owner. Expiration is measured from the document's creation time, is disabled by `BANKEASE_RETENTION_HOURS=0`, and cancels processing jobs before deleting data to prevent worker resurrection. Optional revision uploads link to the latest same-type owner document with a monotonically increasing version and previous-version reference. Revision history omits source paths; comparison reuses the evidence-bearing loan or statement comparison services. OCR loan and policy fields carry an extraction method and source-page bounding box when matched, and OCR-derived analyses require human review while allowing owner field confirmation. PDF/image statement rows retain page and passage evidence; XLSX statement rows retain source worksheet and row references. Statement checks use exact minor-unit arithmetic and flag balance differences and duplicate candidates as review signals. Owners can save revision-checked transaction corrections; effective values and append-only correction history remain separate from imported normalized values and original evidence. New statement comparisons use effective values while balance reconciliation remains anchored to imported rows. Loan and policy field corrections preserve extracted values and evidence while persisting effective values and history; EMI calculations remain loan-only. Loan and statement comparisons retain owner-scoped result/evidence snapshots and reopen or export those stored results without rerunning extraction. Comparisons are removed with either source document and statement rows/correction history are included in account data export. Unrecognized layouts receive a review status. Document list, read, preview, version history, transaction page, compare, report, ask, calculate, correction, and delete operations resolve the current session and query with its owner ID. A document ID alone does not grant access.

Explicitly titled KYC/customer-identification forms with multiple labeled fields use a separate bounded extractor for full name, birth date, and address. It does not extract government identity numbers, classify standalone ID cards, or verify identity/authenticity. KYC field evidence and owner corrections are persisted with the document; KYC text is excluded from global full-text search and assistant Q&A. The dashboard provides a dedicated owner-scoped KYC library and shows the limitations beside the extracted fields.

Explicitly titled audit reports expose only labeled metadata and source passages under recognized opinion, basis, emphasis, key-audit-matter, and findings headings. Documents remain in human review; passages are quoted without deciding whether a reported issue proves error or misconduct. Owner-scoped Q&A cites the original page text.

Financial-statement documents use a label-only total extractor. A same-page balance-sheet equation is checked with decimal arithmetic; comparative rows, conflicting values, and missing inputs remain for review. Original unit/currency text and source evidence are retained, and no conversion or accounting interpretation is made. Owner field corrections recompute the check atomically with the field update in the configured repository. The calculation is included in owner-scoped document details, search findings, dashboard counts, and document reports.

Two owned financial-statement PDFs can be compared using matching labeled totals. A single unambiguous written-month or ISO period label is exposed with page evidence when present. The comparison computes a numeric delta only when both cited rows state matching currency and scale tokens; absent, conflicting, or table-header-only unit metadata does not produce a delta. Comparisons are stored as owner-scoped snapshots and can be reopened or downloaded as a PDF. No period, accounting interpretation, or reporting unit is inferred.

## Document processing jobs

In development, uploads are bounded and saved under a generated private filename before a small owner/document job record is queued. The API worker claims due jobs through a Mongo atomic lease or the locked single-process JSON repository, then reads the source only after rechecking the document owner. OCR stays in its bounded subprocess. Jobs track attempts, schedule, and a time-limited worker lease with periodic renewal; stale leases are reclaimed after a worker restart. Transient server failures retry up to the configured attempt count with backoff; validation failures become `failed`. Startup repairs processing records missing a job. Owners can poll status and retry failed analyses. Deletion removes the job, and the worker verifies its lease before and after saving a result to avoid recreating deleted records. `APP_ENV=test` keeps uploads synchronous by default for deterministic tests.

## Development persistence

Local JSON is selected by default. Auth records are atomically replaced JSON files; analysis records and extracted page text are owner-scoped JSON. MongoDB can be selected with `BANKEASE_STORAGE_BACKEND=mongodb`; metadata and page chunks carry `owner_id`, and indexes are initialized during startup. No live Mongo deployment or migration has been verified.

## Boundaries

The current rate limiter is process-local. Development verification and password-reset links are returned only for loopback/test environments; no outbound email provider exists. Local source files and extracted text are not encrypted at rest. Production startup stays blocked until email delivery, encryption and host ACLs for private local storage, distributed abuse controls, deployment/security operations, and live database verification are complete. OCR is optional and depends on a separately installed Tesseract engine; live Mongo retention behavior, trained model inference, real-engine OCR quality, mixed-page statement extraction, and branch-scoped reviewer access are not verified or implemented.
