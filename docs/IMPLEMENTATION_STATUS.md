## Current product

The dashboard uses a responsive white/blue shell across customer and review workflows, owner-scoped summary cards, evidence search, recent-document actions, rule-finding categories, loan calculations, and a right-side assistant. Dashboard counts and charts come from API records and deterministic calculations. Loan PDFs extract explicitly labeled first-installment, loan-maturity, and interest-reset date candidates with page evidence; insurance policy expiry is also supported. A date appears as an upcoming obligation only after its owner saves a correction/confirmation. Ambiguous numeric dates remain for review, recurring EMI dates are not inferred, and the calendar shows the confirmation plus source passage. Insurance extraction is conservative and rule-based: it covers labeled policy number, insurer, product, policyholder, sum insured, premium, start/expiry dates, and selected clause passages. Conflicts and unclear currency remain for review; it does not establish active coverage or claim eligibility. Explicitly titled KYC/customer-identification forms can extract only labeled full name, birth date, and address fields; government identity numbers are excluded, KYC content is omitted from global full-text search and assistant retrieval, and no identity or authenticity verification is claimed. Financial-statement PDFs extract labeled totals and check the same-page balance-sheet equation with source evidence; comparative-column ambiguity remains for review, and values are not converted or assigned an assumed currency. Owner corrections recalculate the check. Explicitly titled audit reports retain labeled metadata and quote passages under recognized opinion, basis, emphasis, key-matter, and findings headings, with human review and no generated audit conclusion. Unknown readable PDFs are marked `needs_review` with an explanation rather than presented as structured analysis. The assistant persists owner-scoped general and document conversations, retrieves page evidence from selected authorized loan, insurance, financial-statement, or audit-report documents and extracted-section evidence from DOCX files and transaction-row evidence from authorized statements, and streams generated answers through the backend. Document results include filename, document ID, page, and passage; external web results are labeled and linked when configured. A deterministic extractive fallback remains available without a model. Local development defaults to JSON persistence unless MongoDB mode is configured.

Uploads now use a durable background queue in development: private source bytes stay in file storage, jobs hold only owner/document references, Mongo workers claim with atomic leases, local JSON mode uses a locked single-process repository, and worker startup recovers orphaned processing records. Status is owner-scoped, failures are bounded/retryable, and document/account deletion removes queue records. `GET /health` reports the actual worker-thread state. `APP_ENV=test` retains synchronous uploads by default.
BankEase AI has a FastAPI analysis API and a Next.js App Router frontend written in React and TypeScript with Tailwind CSS. It extracts loan terms and clauses from selectable-text PDFs and Tesseract-readable scanned PDFs or PNG/JPEG/TIFF images, and imports supported bank statement CSV/XLSX rows, recognizable selectable-text PDF tables, or OCR tables from fully scanned PDFs with a supported header/column layout. Statement rows retain page, worksheet, or source-row evidence; OCR rows also retain bounding boxes, and every OCR-derived statement remains under human review. XLSX parsing is read-only, rejects macros and external links, and does not evaluate formulas. Raster image OCR is size-bounded and uses a temporary in-memory PDF while retaining the original image privately. Mixed scanned/selectable-text PDFs and unsupported table layouts are explicitly sent to review rather than silently combining partial rows. Statement imports support balance reconciliation, duplicate candidates, search, inclusive date filters, and pagination. Statement owners can correct date, description, signed amount, and running balance; revisions retain imported values, original cells, evidence, reason, and correction history. New statement comparisons use effective corrections, while source reconciliation is unchanged. Owners can request an assigned staff review of a statement row; the reviewer receives an evidence-bearing snapshot of imported and effective values, and decisions/comments are audited without changing source or corrections. Accepted original PDFs, scanned images, DOCX files, CSVs, and XLSX files are stored under generated names in private local storage and shown in authenticated owner-checked previews. Document and account deletion remove originals. Revised copies can be linked into owner-scoped version families, opened, uploaded as the next revision, and compared using the existing evidence-bearing loan or statement comparison workflows. Account settings provide JSON metadata export and a capped ZIP export containing data, a manifest, transaction correction history, and available originals. OCR loan pages and matching field bounding boxes are labeled, and OCR documents require human review. The app also answers supported PDF questions with page citations and DOCX text questions with extracted-section citations, calculates reducing-balance EMI, compares two loan offers, and exports reports. The browser UI includes registration, verification, login, password recovery, document review, owner-only loan and statement corrections with visible history, statement-row review requests, saved loan and statement comparison history with snapshot reports, account settings, session revocation, data export, and account deletion. Saved corrections affect calculations/comparisons while the imported source values and evidence remain unchanged.

Account password hashes use Argon2id. Session and verification/reset tokens are stored as hashes; sessions use opaque HttpOnly cookies and CSRF checks. Document queries and the document list are scoped to the authenticated owner. Owner-requested loan-field review tasks can be assigned by a configured administrator to verified staff accounts; assigned reviewers see only their task's selected field evidence. Role changes and review actions are audited. Local development uses JSON persistence by default; MongoDB mode is available but a live server has not been checked.

The app remains a prototype. Production startup is deliberately blocked until production email, encryption and host ACL controls for private local storage, distributed rate limits, deployment controls, and MongoDB operations are verified. A bounded retention sweep now runs in the document worker every 15 minutes by default, and uploads also sweep the current owner's expired records. It removes source files and linked analyses, comparisons, conversations, jobs, review tasks, and task audit events. Live Mongo cleanup behavior and deletion from backups remain unverified. OCR requires system Tesseract and has only been exercised with mocked OCR output; real-engine accuracy and latency are not measured. A GPT-2 LoRA document-type classifier was fine-tuned as an isolated synthetic research experiment, scored below deterministic rules, and is not used by the app. Approved real public training data remains absent.
